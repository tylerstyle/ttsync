## Focus Area Verification

1. **Filters never lost (`SourcesViewModel.kt`, `SourcesScreen.kt`, `FilterEditorState.kt`, `Navigation.kt`):**
   - **Stored filters preserved by default:** `SourcesViewModel.optionsOf` populates each `SourceOption.filter` from `SourceCalendar.activeFilter` with `filterEdited = false`. On save, `SourcesViewModel.selectionOf` copies the stored `SourceCalendar` (`byId[option.id]?.copy(name = name)`) and only replaces `filter` when `option.filterEdited == true`. Opening the editor and closing it without net changes (`filter == it.filter` in `closeFilter()`) leaves `filterEdited = false`.
   - **Toggling checkboxes preserves drafts:** `SourcesViewModel.toggle` flips `selected` without resetting `filter` or `filterEdited`, so unticking and re-ticking a calendar keeps its draft filter (`SourcesFilterTest.aDeselectedAndReselectedCalendarKeepsItsDraft`).
   - **Setup flow vs. Settings flow:** During initial setup (`setup = true`, `hasTarget = false`), `SourcesViewModel.save` stores the selected calendars together with their filters before navigating to `SetupStep.TARGET`, so the first sync runs with the filters already in place (`SourcesFilterTest.aFilterSetDuringSetupIsSavedBeforeTheFirstSync`). From Settings (`setup = false`, `hasTarget = true`), saving a changed filter triggers `scheduler.runNow(full = true, trigger = SyncTrigger.SETUP)` in `UserActions.saveSources`.
   - **Back from the editor (`BackHandler` vs. `NavDisplay`):** In [SourcesScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/SourcesScreen.kt#L75-L88), `BackHandler(onBack = viewModel::closeFilter)` is composed inside `SourcesScreen` (which is nested inside `NavDisplay`'s entry content in [Navigation.kt](app/src/main/kotlin/de/tergelius/ttsync/Navigation.kt#L67-L75)). Because `OnBackPressedDispatcher` / `NavigationEventDispatcher` dispatches handlers in LIFO (innermost-first) order, `BackHandler` in `SourcesScreen` takes priority over `NavDisplay`'s back handler in Settings mode and prevents activity finish in Setup mode. Both the top app bar back button (`onBack = actions.done`) and system back call `closeFilter()`, keeping the edit as a draft.
   - **Configuration changes & language switches:** `SourcesViewModel` holds `SourcesUiState` (including `FilterEditorState` while the editor is open) in the nav entry's `ViewModelStore` (`rememberViewModelStoreNavEntryDecorator()`), surviving rotation and configuration changes. Because localized label colour names, filter summaries, and `(filtered)` suffixes are resolved at composition time via `LocalResources.current` ([FilterText.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/FilterText.kt#L56-L84)), changing the device language updates the UI immediately.
   - **App resume:** `SourcesViewModel.onResume()` only reloads if `loadError == SourcesError.SIGN_IN && !loading` (when the initial calendar fetch failed before any options were shown), so switching apps and returning never overwrites in-memory drafts or an open editor.

2. **Merged "Remove copies?" confirmation dialog (`SourcesViewModel.kt`, `SourcesScreen.kt`, `UserActions.kt`):**
   - `SourcesViewModel.save()` computes `change = actions.sourceChange(selected)` and sums `actions.filterImpact(it.id, it.activeFilter)` across `change.filterChanged` only when `change.hasTarget` is true.
   - Because `change.filterChanged` only inspects calendars that remain in `selected`, a calendar whose filter was edited and then deselected in the same session is counted only in `change.removed` and not double-counted in `filteredCopies`.
   - When ` !change.removesCopies && filteredCopies == 0` (e.g. during setup, widening a filter, or adding a filter that excludes 0 existing in-window copies), no dialog is shown and `apply(selected)` runs immediately.
   - When `change.removesCopies || filteredCopies > 0`, a single `ConfirmDialog` is shown with `confirmText(confirm)` ([SourcesScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/SourcesScreen.kt#L115-L142)), combining `sources_remove_calendars` and/or `sources_remove_filtered` with `sources_remove_untouched` and falling back to `status_target_unknown` when `targetName` is null.

3. **Compose correctness, consistency, accessibility, and edge-to-edge (`FilterEditorScreen.kt`, `SourcesScreen.kt`, `SettingsScreen.kt`, `StatusScreen.kt`):**
   - `FilterEditorContent` uses `TtScaffold` and `BottomActionBar` ([Components.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/common/Components.kt#L61-L131)), which apply `WindowInsets.safeDrawing` (including IME insets when editing the word fields) and `MaxContentWidth` (640 dp).
   - `FilterLine` ([SourcesScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/SourcesScreen.kt#L212-L243)) uses `heightIn(min = 48.dp)` and `clickable(role = Role.Button, onClickLabel = stringResource(R.string.sources_filter_open))`.
   - `LabelSwatch` ([FilterEditorScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/FilterEditorScreen.kt#L180-L203)) sets `contentDescription` to the localized colour name (or `"Custom colour"` / `"Eigene Farbe"`), and suppresses it via `.takeUnless { it == shownName }` when an unnamed label already displays its colour name as the row title, avoiding duplicate TalkBack announcements.
   - `FilterEditorState.toString()` and `MemberChoice.toString()` redact calendar names, member names, user IDs, and search terms.

4. **EN/DE strings (`values/strings.xml`, `values-de/strings.xml`, `LabelColorStringsTest.kt`):**
   - All English and German strings and plurals are natural, accurate, and grammatically consistent (including dative `"aus %2$s"` with `status_target_unknown` = `"dem Zielkalender"`, masculine pronoun `"er"` for `"der Termin"` in `filter_intro` / `filter_include` / `filter_exclude`, and `"%d Ausschlusswort"` / `"%d Ausschlusswörter"` for `filter_summary_skip_words`).
   - `LabelColorStringsTest` verifies all 25 colour strings in both `values/strings.xml` and `values-de/strings.xml` against the spec (including avoiding TimeTree's German `"Morden cyan"` typo) and checks `LabelColor.nameRes()`.

5. **Documentation (`docs/DESIGN.md`, `README.md`, `docs/DEVELOPMENT.md`, `docs/DEVICE-TESTS.md`) & Phase 1 NIT fixes (`b4ef761`):**
   - All documentation sections match the code and string resources in both English and German, use only synthetic example names, and clearly mark 0.2.0 device tests (steps 15–21 and B3 verification) as not yet run on the device.
   - Commit `b4ef761` (merged in `7e9828b`) cleanly resolved both Phase 1 review nits (`unmanagedMarked` in `SyncEngine.scan` and the two additional tests in `SyncEngineFilterTest`).

6. **Opinion on Risk 3 (Should Back on `Sources` with unsaved filter edits ask "Discard changes?" instead of dropping them silently?):**
   - **Recommendation:** Keep it as-is for 0.2.0 (no blocker or required change), or optionally add a lightweight confirmation only when `options.any { it.filterEdited }` in non-setup mode if device testing shows confusion.
   - **Reasoning:**
     - Inside `FilterEditorScreen`, both **Done** and **Back** already keep the edit as a draft, so pressing Back inside the editor never loses work.
     - On `SourcesScreen` itself, dropping unsaved changes on Back matches how checkbox changes on `SourcesScreen` and radio selection changes on `TargetScreen` already work. The editor also shows `filter_save_note` (*"The filter is saved together with the calendar list"*), and `SourcesScreen` keeps a prominent sticky bottom bar with **Save** / **Next**.
     - The only subtle UX difference between a filter edit and a checkbox toggle is that the user already tapped a primary **Done** button to leave `FilterEditorScreen`, which can feel like a commit if they then press Back in the top bar of `SourcesScreen` instead of **Save** at the bottom. Still, adding a "Discard changes?" dialog requires new EN/DE strings and state for a rare path; it is not needed before 0.2.0 device testing.

## Findings

### 1. [NIT] `ChoiceRow` in `FilterEditorScreen` (and `SourceCheckRow` in `SourcesScreen`) can be shorter than the 48 dp minimum touch target height
- **Location:** [FilterEditorScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/FilterEditorScreen.kt#L151-L157), [SourcesScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/SourcesScreen.kt#L247-L258)
- **Problem:**
  Because `Checkbox(checked = selected, onCheckedChange = null)` has `onCheckedChange = null` (so the parent `Row` handles toggling as a single accessibility node), Material 3 does not apply `minimumInteractiveComponentSize` (48 dp) to the `Checkbox`. With a single-line `bodyLarge` label and `.padding(vertical = 4.dp)`, each row is ~32 dp tall, whereas `FilterLine` in [SourcesScreen.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/sources/SourcesScreen.kt#L217) explicitly applies `.heightIn(min = 48.dp)`.
- **Concrete Fix:**
  Add `.heightIn(min = 48.dp)` before `.toggleable(...)` on `ChoiceRow` (and optionally `SourceCheckRow`):
  ```kotlin
  Row(
    modifier =
      Modifier.fillMaxWidth()
        .heightIn(min = 48.dp)
        .toggleable(value = selected, role = Role.Checkbox, onValueChange = { onToggle() })
        .padding(vertical = 4.dp),
    verticalAlignment = Alignment.CenterVertically,
  )
  ```
