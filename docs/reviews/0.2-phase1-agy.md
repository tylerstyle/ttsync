## Focus Area Verification

1. **Safety of leftover cleanup, `Desired.Absent` for filtered events, and `filterImpact` ([app/src/main/kotlin/de/tergelius/ttsync/sync/SyncEngine.kt](app/src/main/kotlin/de/tergelius/ttsync/sync/SyncEngine.kt), [app/src/main/kotlin/de/tergelius/ttsync/mapping/EventMapper.kt](app/src/main/kotlin/de/tergelius/ttsync/mapping/EventMapper.kt)):**
   - **Foreign rows:** Untouched. `gateway.findMarkedRows(target)` only returns rows in the target calendar whose description ends with a valid `[ttsync:<32-hex-uuid>]` marker, and every delete/update goes through `CalendarGateway.apply` with R1 pre-read marker verification and R2 single-row `_ID` + `DESCRIPTION IS ?` preconditions.
   - **Unknown UUIDs, paused calendars, and unreadable events:** `activeWrites` and `activeFiltered` are populated exclusively from `active` (`!it.paused`) selected calendars and explicitly exclude `work.skippedUuids`. Paused calendars, unknown UUIDs, deactivated events, and birthdays/memos never enter `activeFiltered`.
   - **30-day window:** In `DefaultEventMapper.map`, `shape.endAt < windowStart` is checked before `filter.matches(event)`, so out-of-window events are omitted from both `desired` and `filtered`. In `plan(work)`, mapped `Desired.Absent` rows are deleted only when `mapping.endAt >= windowStart`.
   - **`filterImpact` accuracy:** `filterImpact` decodes the calendar's stored snapshots (which include all live events regardless of any current filter) and counts `db.mappings.forCalendar(ttCalId)` with `it.targetCalId == target.calendarId && it.uuid in excluded && it.endAt >= windowStart` — matching the exact condition under which `plan(work)` deletes mapped copies on the subsequent `FULL` run.

2. **`FULL` forcing and `filter_hash` commit ordering ([app/src/main/kotlin/de/tergelius/ttsync/sync/SyncEngine.kt](app/src/main/kotlin/de/tergelius/ttsync/sync/SyncEngine.kt), [app/src/main/kotlin/de/tergelius/ttsync/ui/UserActions.kt](app/src/main/kotlin/de/tergelius/ttsync/ui/UserActions.kt)):**
   - `fullReason` triggers `SyncMode.FULL` (`"filter changed"`) whenever `cursor.filterHash != work.filterHash`, where `work.filterHash` is `source.activeFilter?.fingerprint()` (`null` for `null` or empty filters).
   - `cursor.filterHash` is written only in `commit(work)` after `applyPlan(work, ops)` completes for that calendar. If a run fails before or during a calendar's writes, the old `filterHash` remains in `cursor` and the next run repeats `FULL`.
   - `UserActions.saveSources` calls `scheduler.runNow(full = true, trigger = SyncTrigger.SETUP)` when `change.filterChanged.isNotEmpty()`, bypassing the 60 s manual-run gap.

3. **0.1.x compatibility ([app/src/main/kotlin/de/tergelius/ttsync/settings/StoreCodec.kt](app/src/main/kotlin/de/tergelius/ttsync/settings/StoreCodec.kt), [app/src/main/kotlin/de/tergelius/ttsync/store/SyncSchema.kt](app/src/main/kotlin/de/tergelius/ttsync/store/SyncSchema.kt), [app/src/main/kotlin/de/tergelius/ttsync/timetree/Dtos.kt](app/src/main/kotlin/de/tergelius/ttsync/timetree/Dtos.kt)):**
   - **Settings & `SourcesViewModel`:** `StoreCodec` leaves `encodeDefaults = false` and sets `ignoreUnknownKeys = true`, so 0.1.x `sources` and `last_report` JSON round-trip byte-for-byte when unfiltered. `SourcesViewModel.selectionOf` copies existing `SourceCalendar` entries from storage so filters survive checkbox toggles on the Sources screen.
   - **Schema 2 → 3:** `ALTER TABLE cursor ADD COLUMN filter_hash TEXT` leaves existing rows with `filter_hash = NULL` (no filter), matching unfiltered 0.1.x sources without forcing an unnecessary `FULL` run.
   - **Cached labels:** `TtLabel`'s new `color`, `defaultColor`, and `order` fields default to `null`, so `cursor.labels_json` written by 0.1.x decodes cleanly and behaves like 0.1.x until the next `FULL` run refreshes the calendar's labels.

4. **Override rule ([app/src/main/kotlin/de/tergelius/ttsync/mapping/EventMapper.kt](app/src/main/kotlin/de/tergelius/ttsync/mapping/EventMapper.kt)):**
   - `parentOf` and `children` are built before filtering, and every event is judged on its own fields (`labelId`, `attendees`, `title`, `note`, `location`).
   - When a series matches and an override does not, the series keeps its own `EXDATE` and its `unmatchedOverrides` count still considers the filtered override; `parentOf` still links the override to the series so `INCREMENTAL` runs re-check the parent.
   - When an override matches and its series does not, the override is written as a standalone non-recurring event (`rrule = null, exdate = null`) and the series is `Desired.Absent`.

5. **Implementer's deviations:**
   - **1. Lenient decoding of new DTO fields (`LenientSerializers.kt`):** Agree. Prevents unexpected shapes in filter-only metadata from failing `GET /calendars` or skipping valid events.
   - **2. No `EventMapper.VERSION` bump for B3:** Agree. `SpecHash` already detects the added `Label: <English colour name>` line on the next `FULL` run and rewrites only the affected copies instead of forcing a version-bump resync across all calendars.
   - **3. `filterImpact` does not take the run `LOCK` and counts mapped copies only:** Agree. Avoids blocking the UI confirmation dialog behind a network sync run; unmapped leftovers only exist after dropped mappings or a fresh reinstall before the first sync completes.
   - **4. `"filter changed"` ordered after `"no high-water mark"` / `"no FULL recorded"` in `fullReason`:** Agree. All branches run `FULL`, and first-sync reasons are more descriptive on initial setup.
   - **5. `EventFilter.fingerprint()` preserves term case:** Agree. Keeps the user's original casing in `normalized()` for the UI while costing at most one no-op `FULL` run on a case-only edit.
   - **6. Added `SourceChange.filterChanged` and `UserActions.filterImpact`, version bump deferred to release:** Agree.

## Findings

### 1. [NIT] `unmanagedMarked` in `scan` counts mapped copies that the same run's diff is about to delete
- **Location:** `app/src/main/kotlin/de/tergelius/ttsync/sync/SyncEngine.kt:894-905`
- **Problem:**
  In `scan(withDuplicates = true)`, mapped rows of filtered events (`id == mapped`) are skipped when building `leftoverIds` because Step 5 (`plan`) will delete them as `Kind.DELETE`:
  ```kotlin
  val mapped = mappingFor(uuid)?.eventId
  for (id in ids) {
    if (id == mapped || id in claimed) continue
    ...
    leftoverIds += id
  }
  ...
  unmanagedMarked = rows.count { it.uuid !in activeWrites && it.eventId !in leftoverIds }
  ```
  Because `scan` runs before `plan` and `applyPlan`, those mapped in-window rows of `activeFiltered` (and any other mapped rows that `plan` will delete in Step 7) are neither in `activeWrites` nor in `leftoverIds`, so `unmanagedMarked` counts them as "unmanaged marked rows left alone" on the run that deletes them (for example, in `SyncEngineFilterTest.narrowingRunsFullOnceAndDeletesExactlyTheExcludedCopies`, `report.counts.unmanagedMarked` is `4` instead of `2` on the narrowing run, then drops to `2` on the next `FULL` run).
- **Concrete Fix:**
  Exclude mapped in-window rows of active calendars from `unmanagedMarked` (or track the `mapped` event IDs of `activeFiltered` when `mapping.endAt >= windowStart` alongside `leftoverIds` when computing `unmanagedMarked`):
  ```kotlin
  val activeMappedDeletes =
    mappings.values
      .filter {
        it.targetCalId == target.calendarId &&
          it.endAt >= windowStart &&
          it.uuid !in activeWrites &&
          active.any { w -> it.ttCalId == w.id && it.uuid !in w.skippedUuids && (w.desired[it.uuid] == Desired.Absent || (w.provesAbsence && it.uuid !in w.fetchedUuids)) }
      }
      .mapTo(HashSet()) { it.eventId }
  unmanagedMarked =
    rows.count {
      it.uuid !in activeWrites && it.eventId !in leftoverIds && it.eventId !in activeMappedDeletes
    }
  ```

### 2. [NIT] Add unit tests for `INCREMENTAL` event edits crossing a filter boundary and sequential filter narrowing in `filterImpact`
- **Location:** `app/src/test/kotlin/de/tergelius/ttsync/sync/SyncEngineFilterTest.kt:48-107`, `app/src/test/kotlin/de/tergelius/ttsync/sync/SyncEngineFilterTest.kt:232-277`
- **Problem:**

  2. **`filterImpact` when narrowing from an already-active filter `F1` to a stricter filter `F2`:** verifying that after `noMeals` is synced (leaving `A2` and `A3` in `snapshots` but not in `mappings`), `filterImpact(CAL_A, nothing)` returns `2` (only `A1` and `SERIES`), and `filterImpact(CAL_A, noMeals)` returns `0`.
- **Concrete Fix:**
  Add these two tests to `SyncEngineFilterTest`.
